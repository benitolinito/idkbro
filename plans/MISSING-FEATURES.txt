1. File adding and context
There are really three separate features:
- Workspace file creation: already supported. The file watcher and manifest synchronize create/rename/delete operations in [collaboration.ts (line 82)](/Users/benlin/Documents/idk-bro/apps/vscode/src/collaboration.ts:82).
- Prompt attachments: missing. Prompts currently carry only text, model, and effort in [protocol/index.ts (line 201)](/Users/benlin/Documents/idk-bro/packages/protocol/src/index.ts:201).
- Binary/image files: currently intentionally unsupported by the collaborative workspace.
The composer should support:
- @filename autocomplete
- Attach current file or selection with exact line ranges
- Attach a folder as searchable scope
- “Add open editors”
- Problems-panel diagnostics
- Selected terminal output
- Images/screenshots
- Context chips showing exactly what every collaborator sent
For collaboration, attachments should include a content hash or snapshot—not merely a path—so everyone knows precisely which version the agent received.
2. Agent modes
I would expose these beside the model selector:
- Plan — inspect and propose, no workspace changes.
- Ask — require approval for edits and commands.
- Auto-edit — allow file edits, ask before risky commands/network access.
- Auto — continue within the sandbox; host-only and explicitly enabled.
Claude currently offers comparable plan and permission modes. Claude permission modes.
Important: these modes must be enforced by the host authority and adapters. They should not be implemented by adding “please don’t edit” to the prompt. Participants also shouldn’t be able to select a mode exceeding the host’s room policy.
3. Checkpoints and granular review
This is probably the most important safety feature after modes. Claude automatically checkpoints edits and supports rewinding files and conversations. Claude checkpointing docs.
For MultiCode:
- Create a checkpoint before every prompt.
- Record each agent result as a reversible transaction.
- Add Undo turn, Revert file, and Reject hunk.
- Only apply an inverse patch when current hashes still match.
- If a collaborator changed the same lines, open a conflict proposal instead of overwriting them.
MultiCode already has bootstrap checkpoints, but those are synchronization infrastructure—not user-facing agent undo.
Best next milestone
I’d build these together as one “controlled agent workflow” release:
1. @ file/selection context and attachment chips.
2. Plan / Ask / Auto-edit mode selector.
3. Editable plan approval card.
4. Per-file accept/revert and Undo turn.
5. Host participant-permission popover.
That set would close the largest experience gap with Claude Code and Codex while strengthening MultiCode’s actual differentiator: several people safely directing and reviewing one shared agent.
